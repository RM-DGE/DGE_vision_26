# RobotModel4 v0.70：双轴几何窗口与最新 IMU 发弹判断

2026-11-18

## 本次范围

普通 Aimer → Shooter 链路新增双轴几何窗口和最新 IMU 时效检查。当前构建入口 `standard`、`sentry_DGE` 已接入；未启用的旧入口仍使用几何检查接口，不能据此认定其已完成姿态时间改造。EKF 算法及日志版本标识仍为 v0.62。本版本不加入动态窗口、选板滞回、边界预瞄或 MPC 策略。

- 图像解算继续使用曝光时刻姿态；Shooter 单独读取最新真实 IMU 样本。通过 Solver 的相同外参转换，但不修改图像使用的姿态。
- 最新样本无效、时间在未来或接收年龄超过上限时，不允许发弹。无外推、无等待新样本。
- yaw 根据预测装甲板左右边缘计算角度范围，取较小的对称半窗；pitch 使用上下边界角差，并保留斜板高度收缩的保守近似。
- 删除转速放宽 yaw 容差、18° 跳变分支和相邻指令跳变门限。最新姿态必须同时通过 yaw/pitch 窗口。
- 取消超过 5 m 后固定角窗的旧行为：固定物理区域的角度窗口随距离继续缩小。

## 配置

已在 `standard3.yaml`、`sentry.yaml`、`daedalus.yaml` 中显式配置；其他配置未提供时使用同样默认值。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| shoot_width_small_m | 0.12 | 小板允许区域完整宽度，m |
| shoot_width_large_m | 0.23 | 大板允许区域完整宽度，m |
| shoot_height_m | 0.08 | 允许区域完整高度，m |
| shoot_max_imu_age_ms | 20.0 | 最新 IMU 主机接收时间的最大年龄，ms |

`auto_fire` 仍是总开关。旧 `first_tolerance`、`second_tolerance`、`judge_distance` 不再参与几何 Shooter 判断。

发布时保留当前现场配置：standard3 的切入/切出角为 75°/15°，高低速预测延迟均为 0.04 s。它们不是动态窗口。

## 验收

格式化后已重新构建：离线算法回归通过（13 组检查，包含双轴几何、选板、姿态时效和 Tracker 用例），时间同步核心回归通过。两个实际入口/串口层另做 C++ 语法检查；未在本机完成依赖相机/检测 SDK 的完整硬件程序链接。旧 A/B 数据不重采、不重复完整回放；离线检查不能证明实车命中率。

小电脑拉取 `test` 后按现场依赖重新配置、编译运行目标，例如：

```bash
git pull --ff-only origin test
cmake -S . -B build -DEKF_ONLY=OFF -DTIME_SYNC_ONLY=OFF
cmake --build build --target standard sentry_DGE -j2
```

若使用本地 `hub` 而非 GitHub `origin`，应按 README 的小电脑同步方式拉取相应远端；不要覆盖现场未提交配置。使用实际车型 YAML 启动现有程序。

最小现场验收：

1. 静止目标近/远各一段：检查跟踪、双轴到位后的发弹，以及偏出窗口后停火。
2. 正/反向旋转各一段：检查切板时的发弹时机和明显误发/少发；保留此次配置、提交号和现有可观测记录。
3. 检查实际 IMU 接收间隔及处理耗时，确认 20 ms 时效阈值适合当前链路。当前版本未新增拒绝原因遥测，不能仅凭 `shoot=false` 推断是姿态过期。

## 已知边界

- IMU 时间戳是主机接收时刻，不是传感器采样时刻，无法消除传感器与串口内部延迟。
- Daedalus 随图像帧填充 IMU；处理超过 20 ms 时会因样本过期而停火。应根据实际采样机制评估，不能把这种情况直接归因于几何窗口过窄。
- 几何窗口是围绕弹道补偿指令的近似容差判据，不是弹丸命中概率保证。
- 不自动启动机器人、不自动运行硬件发弹测试。实车验收由操作者执行。
